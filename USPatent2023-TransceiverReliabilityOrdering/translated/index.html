    (57) ABSTRACT

    Packet flows between a transmitter and a receiver in an unreliable and unordered switched packet network may be established as a result of receiving a second packet comprising a second memory operation on a memory address. The transmission of memory load command packets followed by memory store command packets in the packet flow may be serialized, and a synchronization operation may be executed between the transmitter and the receiver when a packet count at the receiver satisfies a number of data packets in the packet flow.

    在不可靠且无序的交换式分组网络中，发送方与接收方之间的包流可能因接收到包含对某内存地址的第二内存操作的第二个分组而建立。在该包流中，内存加载命令分组之后跟随内存存储命令分组的传输可被串行化，且当接收方的分组计数满足该包流中的数据分组数量时，可在发送方与接收方之间执行同步操作。

    1 TRANSCEIVER SYSTEM WITH END-TO-END RELIABILITY AND ORDERING PROTOCOLS

    BACKGROUND

    Communication between processing nodes in multi-processor systems may suffer from gaps in communication error coverage. For example, in a computing system utilizing a signal switching fabric (also referred to herein as a switching network, or just a 'network') between multiple graphics processing units (GPUs), communication errors arising in the switching fabric or the GPUs themselves may not be recoverable and may potentially cause system failure.

    多处理器系统中处理节点之间的通信可能存在通信错误覆盖范围的缺口。例如，在多个图形处理单元（GPU）之间利用信号交换结构（本文中也称为交换网络，或简称为“网络”）的计算系统中，交换结构或GPU自身产生的通信错误可能无法恢复，并可能导致系统故障。

    In such a system, when packets are retransmitted due to transmission errors, packet order in the network may change and duplicate packets may be created. A robust protocol will not only recover from transmission errors but also reorder packets and remove duplicate packets when needed.

    在这样的系统中，当因传输错误而重传数据包时，网络中的数据包顺序可能会改变，并可能产生重复的数据包。一个健壮的协议不仅能从传输错误中恢复，还能在需要时重新排序数据包并去除重复的数据包。

    FIG. 7 depicts an example of a reset time-out when a REQ packet is sent. Because packets have a maximum lifetime, a time-out timer may be used to detect the loss of a packet. A time-out timer could be initiated for every packet sent into the network. However, checking a timer for every outstanding packet creates significant overhead. The schemes described below utilize only one (or two) timer(s) per flow.

    图7展示了发送REQ数据包时重置超时的示例。由于数据包具有最大生存期，可采用超时定时器来检测数据包丢失。可为发送到网络中的每个数据包启动一个超时定时器。然而，检查每个未完成数据包的定时器会带来显著开销。下述方案每个流仅使用一个（或两个）定时器。

    A single timer per flow may be reset every time a REQ is sent. If the timer expires and there are outstanding REQs, a REQ or RSP has been lost and a GBK/GBKACK sequence is triggered. In the example in FIG. 7, the timer is started when REQ1 is sent, and reset when REQ2 and REQ3, respectively, are sent. Since RSP1 is lost, the timer times out, triggering a GBK/GBKACK handshake.

    每个流的单个定时器可在每次发送REQ时被重置。如果定时器超时且存在未完成的REQ，则某个REQ或RSP已丢失，并触发GBK/GBKACK序列。在图7的示例中，定时器在发送REQ1时启动，并分别在发送REQ2和REQ3时重置。由于RSP1丢失，定时器超时，触发GBK/GBKACK握手。

    The time-out timer is also started/reset when GBK or FIN are sent to capture errors occurring during GBK/GBKACK

    当发送 GBK 或 FIN 时，超时定时器也会被启动/重置，以捕获在 GBK/GBKACK 期间发生的错误。

    10 and FIN/FINACK handshakes. If any of these packets are lost, a timeout will occur and the corresponding handshake is re-tried.

    10 和 FIN/FINACK 握手。如果这些数据包中有任何一个丢失，就会发生超时，并且相应的握手将重新尝试。

    The time-out time has to be set to a value which is greater 5 than twice the maximum packet lifetime (to cover REQ as well as RSP forwarding times). When the time-out timer expires, there is high confidence that no more RSPs will be received.

    超时时间必须设置为一个大于5的最大数据包生存期的两倍的值（以覆盖REQ和RSP转发时间）。当超时定时器到期时，可以高度确信不会再收到RSP。

    For long flows, it could potentially take a long time for an 10 error to be detected as the timer is reset every time a REQ is sent. Furthermore, a significant amount of reorder buffer space might be consumed because every REQ received after a lost REQ is treated as out-of-order. Different measures may be implemented to prevent this. A maximum flow 15 length may be enforced that bounds the time it takes to report an error and also limits the number of entries in the retransmission and reorder buffers taken up by the flow. Another option is to add a mechanism at the destination that detects that no progress is being made. Such a mechanism 20 may use a timer to detect that entries have not been forwarded for some configured period of time, or limit/bound the consumption of reorder buffers by a flow. Lack of progress may be reported back to the source by a NACK indicating a timeout or excess of buffers used, respectively.

    对于长流，错误检测可能需要很长时间，因为每当发送一个 REQ 时，计时器会被重置。此外，由于丢失的 REQ 之后接收到的每个 REQ 都会被视作乱序，可能会消耗大量的重排序缓冲区空间。可以实施不同的措施来防止这种情况。可以通过设置最大流长度限制来强制界定错误报告所需的时间，并限制流所占用的重传和重排序缓冲区条目的数量。另一种选择是在接收端增加一种机制，用于检测是否没有取得进展。这种机制可以使用定时器来检测在某个设定的时间段内条目未被转发，或者限制/界定某个流对重排序缓冲区的消耗。进展的中断可分别通过指示超时或缓冲区使用过多的 NACK 报告给源端。

    Computing devices, such as central processing units and graphics processing units, implement a memory consistency model, which provides guarantees about the order in which a set of events appear to occur. A memory consistency model is conventionally a memory system implementation problem, because it requires the ordering of memory operations (loads and stores) within a chip. Some memory systems (e.g., Nvidia's NVLink and NVSwitch networked systems) extend the memory model across many computing devices by transporting memory operations over a packet switched network. As network systems scale from tens to thousands of endpoints, enforcing packet ordering in the network becomes onerous and reduces performance. If the network cannot guarantee packet ordering, it will violate the memory consistency model. Because enforcing ordering in the network reduces performance, endpoint devices (the final target of transported memory operations) may reorder packets to enforce a memory consistency model. To reorder packets, an endpoint puts a packet in a reorder buffer until all other relevant packets arrive, and the endpoint appropriately reorders the packets according to the memory consistency model.

    中央处理器和图形处理器等计算设备会实现内存一致性模型，该模型为一系列事件表现出的发生顺序提供了保证。内存一致性模型通常属于内存系统实现问题，因为它要求对芯片内部的内存操作（加载和存储）进行排序。某些内存系统（例如英伟达的NVLink和NVSwitch网络系统）通过分组交换网络传输内存操作，将内存模型扩展到众多计算设备上。随着网络系统从数十个端点扩展到数千个，在网络中强制分组排序变得繁重且会降低性能。如果网络无法保证分组顺序，就会破坏内存一致性模型。由于在网络中强制排序会降低性能，端点设备（所传输内存操作的最终目标）可以对分组进行重新排序，以维护内存一致性模型。为了对分组重新排序，端点会将分组放入重排序缓冲区，直到所有其他相关分组到达，然后端点根据内存一致性模型对这些分组进行适当的重新排序。

Limiting the amount of 30 traffic negatively impacts the throughput of the network.
